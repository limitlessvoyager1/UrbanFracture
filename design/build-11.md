# Build 11 — native controller support

Added browser Gamepad API polling with the standard controller mapping. DualSense / PS5 controls: left stick or D-pad move, Square attack, Cross jump/follow-up, Triangle sword, Circle dodge, L1 block/timed catch, R1 manual grab/release, R2 run, Options start/pause/resume. Cross also confirms/retries checkpoint menus; victory restarts from stage one. Equivalent Xbox controls work through standard mapping.

Controller directions are available before edge-triggered commands, preserving direction+attack throws and forward+special dash. Holds continue blocking/running/combo attacks; catches, jumps and other actions require fresh presses. Stick dead zone .25; trigger threshold .5. Keyboard/touch and controller inputs are combined without writing controller buttons into keyboard held state.

Connection status and a controller guide appear below the game. Unrecognized raw layouts are identified instead of guessing their button indices. Standard browser mapping is required. An active controller disconnect/change pauses play. Focus loss prevents controller activity until focus returns. Start/pause/resume/reconnection require neutral controller input before combat resumes, avoiding accidental held-button actions. No controller emulation or keyboard remapping is required when the browser exposes a standard gamepad.

Validation: unit and actual game.js integration tests cover standard DualSense mapping, sparse device arrays, sticks/D-pad, dead zone, button edges/holds, menu confirmation, pauses, directional special, block/catch, disconnect and focus protection. All existing combat/rendering/full-level regressions pass. Browser QA used a temporary simulated Gamepad API fixture to verify controller detection, Options start/pause and Triangle sword input. No physical controller is available in the testing environment, so physical USB/Bluetooth testing remains a user-side check. Temporary fixture removed before packaging.
