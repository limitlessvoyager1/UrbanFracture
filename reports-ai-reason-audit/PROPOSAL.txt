PROPOSED CORRECTION — AFTER APPROVAL ON A NEW BRANCH
Production scope:
1. dist/ai-observer288.js only for attribution: maintain bounded private per-game/per-actor attempt/decision correlation, with private sequence/identity tokens and observedAt. Never write actor denials/controllers, call admission again, consume RNG, or allocate gameplay action IDs merely to label diagnostics.
2. For an observed attempt, capture before/after action identity and available native evidence. A newly admitted action is an admission outcome; its rejection reason is null. A rejected/no-new-action attempt only uses a reason newly produced and correlated to that attempt. Missing/unobserved reasons remain explicitly unavailable.
3. Use object/sequence correlation, not timestamps alone or request-array length (bounded lists can roll over). Native wrappers may reject with a new denial but no Director row, so Director history alone is insufficient.
4. Observe direct start when it reaches this layer and deduplicate nested enemyAct->start attempts. Preserve original calls, arguments, return values and exceptions. Later outer guards can remain outside coverage; label such state unknown rather than instrumenting every gameplay guard.
5. Add a read-only decision-context projection distinguishing LIVE ACTOR STATE, LAST OBSERVED ATTEMPT, and HISTORICAL NATIVE DENIAL / LAST DIRECTOR REQUEST. Keep raw denied/latestRequest values and timestamps available; make legacy selectionReason refer only to supported current correlation or unavailable text. Do not invent an affirmative why-selected explanation from granted=true.
6. Correlate a last observed admission with the current action only while the action identity still matches; if actions change while recording is off, expire the correlation. Last observed decision remains timestamped history, not an assertion that no later decision occurred.
7. Preserve detached historical rows. New records should carry corrected context; do not rewrite earlier raw outcomes/timestamps. Clear/toggle/reset/time-rewind/actor replacement must reset or invalidate ONLY private observer correlation; raw native state remains untouched.
8. dist/ai-inspector288.js: label raw native history and last observed decision separately from live state, and explain unknown coverage. Keep existing recording controls/source view/exports. Update affected index cache tokens. No change expected in Diagnostics307 because it already consumes observer rows; touch it only if a consumer test proves necessary.
Tests/QA/log: new focused regression suite plus critical registry entry and repair-log update. Update the existing observer assertions only to the clarified diagnostic contract; do not weaken combat/admission checks.
