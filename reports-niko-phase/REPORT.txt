ROOT CAUSE
Native Niko combo stages use once-events at hitFrame185(6,6,8,11), while their general hitAt field deliberately remains999. Audit135.phase used the generic timing-list API and classified all combo startup/contact/recovery as utility/recovery. Native damage and poses were already executing at the authored frames; changing hitAt to fix a label would alter the wrong system.

CORRECTION / SCOPE
Add a pure diagnostic phase branch only for valid, unpaired native Niko combo actions. Before the native hit frame:startup. Around the native contact sample:active. Afterwards:recovery. Use the existing native once-event EPS tolerance1e-7, without modifying action.t or any other state.
The active diagnostic band includes the hit frame through hitFrame+1, matching the generic classifier's one-frame inclusive sampling convention. This allows the30Hz fourth-hit sample, which crosses authored frame11at sample12, to retain an active label. It is not a new collision window, repeated hit opportunity, or command/counter timing rule. Native once-events remain the sole execution owner.
Do not change hitAt999, Audit135.times, Director148.actualTimes, native hitFrame185/total/damage, once() or any other move implementation. Invalid/missing timing metadata, paired choreography, palms, air attacks and other unreviewed Niko moves retain the existing fallback. This fixes the confirmed four-stage combo issue; it is not an invented timing catalog for every Niko ability.
