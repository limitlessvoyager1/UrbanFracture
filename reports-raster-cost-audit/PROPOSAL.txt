URBAN FRACTURE — GROUNDED RASTER COST AUDIT / PERFORMANCE PROPOSAL
UF-AUDIT-026 | 2026-11-12 | Audit only; STOP before production repair

Decision
Readback/raster synchronization is the largest measured grounded-path cost.
There is no proven safe readback-area reduction in this audit. Keep the exact
native poses, sole/crop rules and UF-RENDER-025 time/flash validity correction.
The recommended first repair is bounded reuse of retired, EXACT-SIZE cropped
canvases. This is a modest allocation/copy-cost reduction, not a claimed solution
to the entire performance hold. If approved, implement and measure it separately;
do not promote on analytical microbenchmarks alone.

Proposed repair: bounded exact-size cropped-surface reuse
Evidence: isolated fresh cropped-canvas/copy CPU cost ~.0633ms versus same-size
reuse/clear/copy ~.0027ms.48varying native/blank crop comparisons across four sizes
are byte-identical between fresh and reused surfaces. These are API microprobes,
not an integrated pool or a guaranteed completed-GPU/frame-time improvement.
Trace-only availability model,32idle surfaces /4MiB cap, cold at measured start:
1,241reuses /19fresh allocations across1,260mixed-eight misses (98.49%) in BOTH
confirmation traces. It does not execute a shipping pool or assume unchanged
native rectangles. Shapes are matched by the actual observed width/height.

Scope, if separately approved on a new branch:
1. Only sprites.js private cache-generation retirement and cropped-canvas
   acquisition, plus its index cache token. Keep original miss rendering/readback,
   scans, integer rectangles, transforms, native drawImage arguments and return
   values. No smaller readback, scan-model rewrite or context-hint changes.
2. At a time-generation change, retire previous entries' canvases into a private
   exact-width/height free pool before clearing the active map. Never put an active
   cache image into that pool, never let two live entries alias one surface, and
   never reuse raster CONTENT across time or flash identities.
3. On a miss with a nonempty native crop, borrow only a surface of exactly matching
   dimensions. Clear the complete surface before the unchanged crop copy. If none
   exists, use the original fresh-allocation path. Preserve context settings and
   complete RGBA, including translucent edges. Do not resize a mismatched canvas
   and claim an allocation was avoided.
4. Bound inactive retention independently: proposed32surfaces and4MiB of RGBA
   pixels, whichever is reached first; delete empty size buckets. The pixel budget
   is an accounting limit, not an assertion of actual browser/GPU memory usage.
   Active cache size guard remains unchanged. To keep the first repair narrow,
   do not recycle same-time size-guard evictions; let the existing drop behavior
   stand. Pool objects must not retain actors, actions or game instances.
5. Empty-crop behavior, same-time sharing, flash separation, exact floating clocks,
   nonfinite-time invalidation, paused frames, reset/rewind and original cache-size
   policy remain unchanged. No simulation tick, damage/config, AI, grapple/counter,
   native selector, sole or recovery edit.
6. Add Git-free current-runtime ownership/pixel/memory regressions and one strict
   QA registration, preserve all existing tests and historical receipt gates.
   Update repair log, source-proof and rendered/performance receipts.

Expected benefit / limits
The observed allocation/copy component is only about.36–.39ms per mixed-eight
frame. The microprobe suggests roughly.4ms potential in this workload; that is an
estimate, not a measured integrated saving. Do NOT promise recovery of the earlier
~6–8ms mixed-roster penalty or clearance of the performance hold. Readback and
bounds scanning remain. A larger throughput repair needs separate investigation,
not a speculative renderer rewrite hidden in this patch.

Potential regressions
Borrowing a still-live bitmap corrupts a same-time peer or actor rendered earlier.
Incomplete clearing leaves ghost pixels; dimension mismatch shifts/clips the sole.
Unbounded buckets retain memory across hero/world resets. Canvas backend buffering
may change real savings versus API submission cost. Exact-size hit rate differs
for attacks, costume families, effects and scales beyond these static fixtures.
Keeping a pool introduces new lifetime ownership despite preserving crop math.
Source complexity low-to-medium; verification medium. Existing025hold stays strict.
