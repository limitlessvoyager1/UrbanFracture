# Orion hit registration repair

ORION-A01: hit() previously consumed action/event/target identity before native g.damage accepted the contact. A brief invulnerability interval could reject the first overlap, then suppress all remaining eligible frames even after protection expired.

The permanent hit ledger now consumes only a native accepted result, applied damage or a confirmed guard response (flash, native block counters/timestamp or spent guard defense). Native blocking and armored damage still resolve once. A WeakMap reservation protects synchronous recursive admission and is released in finally; denied contacts remain eligible only when existing move dispatch calls hit again. The hit routine does not schedule retries, extend active frames, clear protection, enlarge range or bypass native admission. One-shot paired/impact events retain their existing once() clocks and release rules. Existing connected/electrical/impact semantics are unchanged.

Approved damage, costs, startup/active/recovery, speeds, range/depth/height, victim choreography and all source artwork are unchanged. The only production edit is the hit() ledger/admission section of dist/orion-combat205.js. The same old module blob14e168c6d33a0afc5a3cc4310099879112bd397c is present in both GitHub and the published source, so this patch applies to each active entry without copying unrelated later gameplay.

New QA242 regression exercises native current-order simulation at30/60/120Hz in both directions, expiry during and after the active window, wake protection, lane/range exclusion, event/target deduplication, native guard with an already-lit flash, guard-cost confirmation, recursive calls, exception cleanup and laser/electric deduplication. The retained old source reproduces the bug. Twenty-four unprotected combo scenarios compare1,680 native frames against the original source, checking damage, resources, clocks, positions and configuration. No alternate movement or collision controller is used.

The first red test capture is preserved. Its initial30Hz expiry fixture also demonstrated that invulnerability lasting beyond the sampled active window must remain a miss; the fixture was corrected to expire inside the original window. A separate retained-source negative test continues to reproduce the real ledger defect. The first equivalence fixture re-evaluated the old module after startup and reset later configuration; it was replaced with a source-substituting current-order loader so both sides receive the same native load order. No production configuration or timing was changed to satisfy either test.

The earlier importer, walking and counter/effects repairs are retained. Full game/artistic/hardware/performance certification, PR18 owner acceptance and manual holds remain open. No merge or branch-protection change is included.
